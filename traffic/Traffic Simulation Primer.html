How the traffic simulation works, and how you author an intersection in it

A microscopic traffic simulation built inside Unreal Engine 5.8. Roads, signals and demand are authored in the editor with tools modelled on Aimsun, then driven by car-following, lane-change and gap-acceptance models at scale. This page is for traffic engineers who will author scenarios or review results.

Overview

The simulation lives in a plugin for Unreal Engine. Every vehicle and pedestrian is an entity in Unreal's Mass framework, which keeps the per-agent data in flat arrays so tens of thousands of agents update each frame. Everything you author is stored in one network asset per level: road geometry, intersections, control plans, demand zones and origin-destination (OD) matrices.

1. NetworkDraw roads (Aimsun sections), join them into nodes, set lanes, pockets, footways and bus stops.
2. ControlOne control plan per node: fixed-time, actuated, or unsignalized with give-way rules.
3. DemandZones on boundary legs, OD matrices per vehicle class and named period, or turn counts estimated to OD.
4. SimulationPoisson arrivals, shortest-path routing, IDM+ car following, LMRS lane changes, gap acceptance.
5. VisualisationInstanced City Sample vehicles and animated pedestrians, signal heads, driver and eye views for review.

Authoring happens in a Traffic Tool editor mode. Its panel holds the tools (Select, Path, Linear, Auto, Node, Lanes, Zone, Connect, Cut, Signal, Transit), three buttons that open the dialogs covered below (Edit Signal Timing, Edit Demand, Switch Demand), a Properties section for the selected element, and simulation controls (speed multiplier).

Units. The data is stored in centimetres and seconds. The dialogs show metres, km/h and seconds where a unit is shown; the signal timing boxes are all seconds even where no unit is printed.

Network model

The network mirrors Aimsun's vocabulary with a few simplifications. A road is a Path (an Aimsun section). Lanes are not separate objects; a Path has a lane count and lane 0 is the leftmost lane in the direction of travel. Intersections are Nodes, and each turning movement is a Connection with its own short connector Path through the box.

How a node is built

  • Select two or more legs and run the Node tool. Each leg's node-facing end is whichever end is nearer the other legs.
  • Every incoming/outgoing pair becomes a turn except U-turns (legs more than 160° apart, or a leg's own opposite direction).
  • Each turn gets a three-point curved connector; left and right turns use the outer lane by default. The Lanes tool edits the lane-to-lane mapping by dragging lane lines.
  • New turns default to: Left = Yield, everything else = None, visibility 50 m. A default control plan is seeded at the same time (see below).
  • The Cut tool slices the roads it crosses and builds an unsignalized node with lane-to-lane through movements.

Signal timing dialog

Select a node and press Edit Signal Timing. The dialog is a dockable tab with a header row, a Timing tab (cycle dial, signal group grid, turn assignment) and a Priority tab (give-way rules per turn). Three control types exist:

TypeHow it runsFields that matter
FixedPretimed cycle. Green state is computed from the clock as (time − offset) mod cycle, so coordinated offsets along a corridor just work.Cycle, Offset, per group Start and Duration, Yellow, All-red
ActuatedGroups run in list order. Each holds at least Min Green, gaps out after Extension seconds with no vehicle within 30 m of the stop bar, and is forced off at Max Green. No phase skipping. Pedestrian recall stretches min green to 7 s WALK plus clearance at 1.1 m/s.Min Green, Max Green, Extension, Yellow, All-red (Start, Duration and Offset are ignored)
UnsignalizedEvery movement runs on its own give-way rule. All-way stop, two-way stop and yield control are Priority-tab presets, not separate types.Give way, Visibility, Conflicts column

A signal group is a set of turns (and crossings) that are green together, what Aimsun calls a signal group and NEMA calls a phase. A turn may belong to several groups and is green whenever any of them is green. That is how a protected-permissive left is expressed: the left sits in a short protected group and again in the through group, where the Yield rule makes it permissive. A non-left turn shared by two consecutive groups carries its green across the transition instead of showing yellow.

What the dial is telling you

  • Twelve o'clock is t = 0 and time runs clockwise; one revolution is one cycle. Each group is an arc: green, then yellow, then all-red. Groups that overlap in time drop to an inner track.
  • Drag an arc body to move its start, the leading handle to change the start while keeping the end, the trailing handle to change the duration. Drags snap to 1 s. The hub is the cycle length box; the thin inner ring is the offset.
  • Rim ticks step by 5, 10, 15, 20, 30, 60, 120 or 300 s, whichever keeps at most 18 ticks.
  • A thin green stripe inside a band marks green carry-over into the next group; a white stripe marks a WALK that carries over.
  • Copy and Paste move timing between nodes but not turn membership. The dialog has its own undo (Ctrl+Z / Ctrl+Y).
Signal heads. Heads are placed by hand with the Signal tool as Through (3-section), Left (4-section, protected arrow or flashing yellow arrow) or Walk displays. Each head binds itself to the node's plan by leg and group; a Describe Binding button reports what it bound to.

Demand and OD dialog

Demand is OD based. You create zones with the Zone tool on the boundary legs, then press Edit Demand. The dialog shows a totals line, two content tabs (OD Matrix and Turns), a row of vehicle-class tabs (Car, Motorcycle, Bicycle, Truck, Bus, Train, Pedestrian, plus custom classes) and a row of named period tabs shared by every class. Each class holds one matrix per period, in veh/h (persons/h for pedestrians).

How the numbers become traffic

  • Arrivals are Poisson at the total authored rate: class and origin are drawn together, then the destination by the cell's share. Each (class, origin) has a virtual entry queue like Aimsun's; a full queue drops arrivals and logs a warning.
  • Vehicle models per class are a project-wide list (City Sample cars, trucks with trailers, buses, cyclists, 30 pedestrian types). One model of the class is picked uniformly at random. There is no per-zone or per-period mix.
  • Routing uses a precomputed shortest-distance table per destination leg. At each node the vehicle picks among routes within 1.3× of the best, so parallel streets share load. Routing is by distance, not travel time, and does not react to congestion.
  • Periods have a name only. Which period is live is chosen by name at run time, from the Switch Demand panel, a Blueprint call, or the console. Each period keeps its own population, and a network is warmed up the first time a period is selected so it starts populated.
  • Turn counts are a convenience input. Only the OD matrix is simulated; Estimate OD writes the matrix from the counts (Proportional, or Adjusted to routing with a damped iteration that reports RMSE).

What it does not do yet

Read this before promising anything to a client. These are gaps as of 21 October 2026, not design decisions.

  • No measures of effectiveness. There are no throughput counters, travel times, delay, queue lengths or level of service, and no CSV export. A developer stall log and debug draws exist. The demand totals line shows authored volumes, not measured.
  • No time-of-day scheduling. Periods are names; someone switches them. There are no arrival profiles within a period and no fixed-headway option.
  • Actuated control is simplified. Detection is a fixed 30 m zone at the stop bar, there is no detector placement, no phase skipping, no ring-and-barrier display; dual-ring plans must be folded into one ring.
  • No roundabouts and no stage diagram other than the cycle dial.
  • Routing is distance based and not congestion aware; no dynamic traffic assignment.
  • Vehicle mix is per class, project wide, not per zone or per period.
  • Transit has bus stops but no transit lines or schedules.
